# 案例演练 02｜B2B SaaS：让采购负责人找到技术证据

**类别：B2B 软件｜性质：教学模拟（不是已获证实的客户成效）｜域名参考：example.com**

## 场景

模拟一家 B2B 软件公司，预算和真实客户数据均未提供。

## 第 1 周：发现问题

1. 明确 ICP、采购周期与安全评估问题。记录前态页面、后台可见状态与问题清单。
2. 建设 API 可靠性、部署、集成限制与成本说明页。写下 10 个真实或待验证的自然问法，标注来源。

## 第 2–3 周：建设

3. 提供可复制请求、响应和错误处理文档。发布 1–2 个高证据页面，不批量铺同质化内容。

## 第 4 周：测量和商业验证

4. 建立销售对话与产品页面之间的来源关联。记录 URL、具体答案、咨询动作、准确来源。

## 验收门槛

- 交付：一次问题研究、一次技术检查、至少一个答案页和一次复测。
- 证据：公开链接、可验证截图、变更记录、原始来源。
- 商业：可用试用申请和有效 Demo 预约衡量商业结果。
- **不填写假想的提及率、引用量、营收、客户名单。** 若没有数据写「待验证」。

## 对抗式追问

这个案例真的有客户需求来源吗？页面是否无需登录可读？是否有人在消费前提出这些问题？所谓 GEO 带来的咨询有没有独立来源证据？
