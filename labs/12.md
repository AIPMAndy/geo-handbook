## 常见失败和处理

GitHub Star 数量不等于真实用户、商机或收入。

如果无法访问某个平台或没有后台权限：填写「未执行 / 无权限 / 无数据」，保留截图和阻塞原因，继续做不依赖权限的部分。不要凭空补零。

## 进阶实操：可直接抄的细节与排障

### 项目能运行，比项目介绍更重要

README 的第一屏先放一句实用价值、支持环境、安装命令、最小输入输出。准备一个 `examples/` 文件夹，提供可以离线运行的输入与预期输出。重要失败要有 FAQ，比如缺少权限、版本不兼容、网络受限、输入格式错误。让另一台全新电脑按 README 独立执行，不要默认作者的本地环境已经配置好。

### 技术内容怎么与 GEO 结合

官网技术介绍页提供目标用户的真实问题与可验证的功能说明，链接到官方 GitHub 代码、文档及 Release；仓库 README 再指回正式产品页和支持路径。每次版本变更写清兼容性、修复与已知限制。可以手工监测 ChatGPT/Bing 对相关技术问题是否出现该文档的 URL，但 Star、GitHub 搜索排名与 AI 引用是不同指标。

### 对抗式验收

让一名没看过源码的开发者在 5 分钟内尝试 Quickstart；失败则记录哪一步缺环境依赖、提示不清或输出不可复现。不要先让 AI 编一个漂亮示例，再把不能运行的代码宣传成「已验证」。
